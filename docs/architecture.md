# 架构说明

## 总览

```
┌───────────────┐   chrome.runtime 消息   ┌──────────────────────────┐
│ Popup / 选项页 │ ◄─────────────────────► │ Service Worker (后台)     │
│  (Vue 3)      │                          │  · 每小时 alarms 检查      │
└───────────────┘                          │  · 抓取 → 合并 → 评估 → 告警│
                                           │  · 角标 = 未读告警数        │
                                           └──────┬───────────┬───────┘
                                                  │           │
                                     ┌────────────▼─┐   ┌─────▼─────────┐
                                     │ index.baidu.com│   │trends.google.com│
                                     │ (登录态网页接口)│   │ (公开网页接口)   │
                                     └──────────────┘   └───────────────┘
                                                  │
                                        ┌─────────▼──────────┐
                                        │ chrome.storage.local│
                                        │ 订阅/序列/告警/状态   │
                                        └────────────────────┘
```

## 数据流

1. `chrome.alarms`（每小时）或手动刷新触发 `runCheck()`。
2. 每个「订阅 × 启用来源 × 关键词」独立抓取（间隔限流），失败仅记录状态，绝不产生趋势告警。
3. 新数据按“重复日期保留最新有效值、缺失不补 0”合并进本地历史（上限 400 天）。
4. `runSubscription()` 对每个「关键词 × 来源」独立评估（两来源不相加、不平均、不比较）。
5. 生命周期状态机（`lifecycle.ts`）负责去重：数据未更新不重算；告警持续期间不重复提醒；
   分数连续 3 个新数据点低于阈值 60% 后恢复；方向反转是新告警。
6. 同一订阅一次运行中的多个触发合并为一条告警记录；角标显示未读数。

## 学习阶段

| 有效点数 | 行为 |
| --- | --- |
| < 14 | 只展示图表 |
| 14–34 | 只运行快速变化规则 |
| ≥ 35 | 完整 7 天 / 28 天算法簇 |
| ≥ 56 | 追加变点检测与历史基线 |

## 模块

- `src/core/` 纯函数领域层，无浏览器 API，直接被 Vitest 测试。
- `src/data/` 抓取器：错误分类（auth / network / parse / rate-limited / unavailable）。
- `src/store/` 仓库层：键空间 `kw:*`，删除订阅时级联清除序列、状态、告警与图标。
- `src/background/` 编排：检查循环、消息处理、角标。
- `src/pages/` UI：popup（卡片 + 双趋势图 + 范围切换）、options（订阅 CRUD、模板卡片、图标选择）。
